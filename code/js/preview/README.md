# SSC Native Preview V1

SSC's native cube preview infrastructure. The state engine and SVG renderer are owned by SSC; `cubing.js` is used only as an independent validation reference.

## Current scope

- Generic NxN state engine for orders 2-7.
- WCA-style outer and wide cube moves used by NxN scrambles, including explicit 3-layer wide moves on 6x6 and 7x7.
- Normalized state output using face identities (`U D F B R L`), never colors.
- Deterministic semantic sticker IDs such as `U1`, `U2`, `F9`.
- Generic mathematical SVG net renderer shared by 2x2-7x7.
- Order-specific 2x2 through 5x5 presentation profiles modeled on csTimer: identical integer-device-pixel stickers over one continuous black rectangle per face, adjustable 1–4 CSS-pixel separators converted to whole physical pixels, no SVG grid strokes, one-third-sticker face gaps, compact outer margins, and a physical-pixel-snapped absolute SVG origin. Extra card space is centered within half a physical pixel instead of stretching a row or column. State mapping remains shared and unchanged.
- The default palette matches csTimer's familiar cube colors: white `#ffffff`, yellow `#ffff00`, green `#00dd00`, blue `#0000ff`, red `#ff0000`, and orange `#ffaa00`. Existing colors in `sscCubeColorsV1` remain authoritative.
- The default preview size is 200%; the existing 150%-500% range, 5% step, viewport clamping, and saved `sscCubePreviewSizeV1` values remain unchanged.
- `cubing.js` reference validation for every NxN order from 2x2 through 7x7.
- Production routing for `222`, `333`, `444`, `555`, `666` and `777` behind one feature flag.
- Legacy preview fallback remains installed for render failures and for non-routed/non-NxN events.
- Development and validation UI at `/preview-lab.html`.

## Modules

```text
ssc-nxn-state.js
  State Engine

ssc-svg-renderer.js
  SVG Renderer

ssc-preview-validation.js
  cubing.js Reference Adapter + normalizeState() + compareStates()

ssc-preview-v1.js
  Public Facade

ssc-preview-v1-integration.js
  Production Routing + Legacy Fallback
```

## Data flow

```text
Scramble
  -> SSCNxNState
  -> normalized face state
  -> SSCSvgCubeRenderer
  -> SVG
```

Validation is intentionally separate from rendering:

```text
Scramble -> SSCNxNState -> normalized SSC state
Scramble -> cubing.js    -> normalized reference state
                         -> compareStates()
```

## Public APIs

```js
SSCPreviewV1.render(container, scramble, '777');
SSCPreviewV1.getState('777', "3Rw U 3Rw' U'");

await SSCPreviewV1.validate({
  eventId: '777',
  count: 100
});

await SSCPreviewV1.validateAll();
```

## Production feature flag

There is one production flag, defined once in `index.html`:

```js
window.SSC_FEATURES = {
  previewV1: true
};
```

When enabled, all standard NxN events from `222` through `777` are routed to `SSCPreviewV1`. Non-routed/non-NxN events continue through the existing preview system.

If V1 throws during a routed render, `ssc-preview-v1-integration.js` logs the failure and immediately calls the captured legacy renderer. If that connected renderer also fails, it makes one final attempt through the existing 2D preview manager.

## Validation baseline

CI validates:

- solved state;
- all quarter, inverse, and double outer turns for `R U F L D B`;
- inverse pairs;
- four-turn identities;
- known algorithms;
- explicit 2-layer wide turns (`Rw Uw Fw Lw Dw Bw`), their inverses/doubles, inverse pairs, four-turn identities and wide-move algorithms for 4x4+;
- explicit 3-layer wide turns (`3Rw 3Uw 3Fw 3Lw 3Dw 3Bw`) with the same regression coverage for 6x6 and 7x7;
- 100 WCA random scrambles per validated event generated by `cubing.js`.

Current state-validation baseline:

- 2x2: `134/134` passing (`100` random + `34` deterministic);
- 3x3: `134/134` passing (`100` random + `34` deterministic);
- 4x4: `167/167` passing (`100` random + `67` deterministic/wide);
- 5x5: `167/167` passing (`100` random + `67` deterministic/wide);
- 6x6: `200/200` passing (`100` random + `100` deterministic/wide/deep-wide);
- 7x7: `200/200` passing (`100` random + `100` deterministic/wide/deep-wide);
- combined: `1002/1002`, zero sticker mismatches.

Rendering regression checks cover solved/scrambled 2x2 through 7x7; all 64 combinations of 2x2/3x3/4x4/5x5, line widths 1–4, and DPR 1/1.25/1.5/2; an additional 80-case 5x5 matrix across preview sizes 150/200/300/400/500%; one continuous background per face; equal frames and internal separators; absolute-origin snapping; unchanged geometry for 6x6 and 7x7; stable semantic IDs; immediate color updates; scramble and wide-move updates; no mirroring transforms; and full-card fit checks. Integration regression verifies V1 routing for `222`/`333`/`444`/`555`/`666`/`777`, preservation of the legacy path for a non-NxN event, the single feature flag, legacy fallback and emergency legacy-2D fallback.

## Safety rules

- Do not delete `cube-preview.js`, `wca-previews.js`, `scramble-display`, or the TwistyPlayer path while V1 still has a legacy fallback dependency.
- Do not add CSS mirroring or face-specific transform patches. Orientation bugs belong in state mapping.
- Do not create a second state engine or renderer for the same NxN path.
- Keep colors out of state data.

## NxN status

The 2x2-7x7 native NxN migration is complete. Every supported order has passed its own state-validation, SVG-rendering and production-fallback gate before being routed to V1. Keep the legacy stack available for non-NxN events and emergency fallback until those paths are migrated independently.
