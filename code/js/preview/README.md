# SSC Native Preview V1

SSC's native cube preview infrastructure. The state engine and SVG renderer are owned by SSC; `cubing.js` is used only as an independent validation reference.

## Current scope

- Generic NxN state engine for orders 2-7.
- WCA-style outer and wide cube moves used by NxN scrambles.
- Normalized state output using face identities (`U D F B R L`), never colors.
- Deterministic semantic sticker IDs such as `U1`, `U2`, `F9`.
- Generic mathematical SVG net renderer shared by 2x2-7x7.
- Palette is applied only in the renderer and comes from SSC's existing `sscCubeColorsV1` settings.
- `cubing.js` reference validation for 2x2, 3x3 and 4x4.
- Production routing for `222`, `333` and `444` behind one feature flag.
- Legacy preview fallback remains installed for render failures and for every event not yet routed to V1.
- Development and validation UI at `/preview-lab.html`.

## Modules

```text
ssc-nxn-state.js
  State Engine

ssc-svg-renderer.js
  SVG Renderer

ssc-preview-validation.js
  cubing.js Reference Adapter + normalizeState() + compareStates()

ssc-preview-v1.js
  Public Facade

ssc-preview-v1-integration.js
  Production Routing + Legacy Fallback
```

## Data flow

```text
Scramble
  -> SSCNxNState
  -> normalized face state
  -> SSCSvgCubeRenderer
  -> SVG
```

Validation is intentionally separate from rendering:

```text
Scramble -> SSCNxNState -> normalized SSC state
Scramble -> cubing.js    -> normalized reference state
                         -> compareStates()
```


## Production feature flag

There is one production flag, defined once in `index.html`:

```js
window.SSC_FEATURES = {
  previewV1: true
};
```

When enabled, `222`, `333` and `444` are routed to `SSCPreviewV1`. Events from 5x5 upward continue through the existing preview system until they pass their own validation and rendering gates.

If V1 throws during a routed render, `ssc-preview-v1-integration.js` logs the failure and immediately calls the captured legacy renderer. If that connected renderer also fails, it makes one final attempt through the existing 2D preview manager.

## Validation baseline

CI validates:

- solved state;
- all quarter, inverse, and double outer turns for `R U F L D B`;
- inverse pairs;
- four-turn identities;
- known algorithms;
- explicit 4x4 wide turns (`Rw Uw Fw Lw Dw Bw`), their inverses/doubles, inverse pairs, four-turn identities and wide-move algorithms;
- 100 WCA random scrambles per validated event generated by `cubing.js`.

Current state-validation baseline:

- 2x2: `134/134` passing (`100` random + `34` deterministic);
- 3x3: `134/134` passing (`100` random + `34` deterministic);
- 4x4: `167/167` passing (`100` random + `67` deterministic/wide);
- combined: `435/435`, zero sticker mismatches.

Rendering regression checks cover solved/scrambled 2x2, 3x3 and 4x4; stable semantic IDs; immediate color updates; scramble updates; no mirroring transforms; and 150/200/300/400 px scale calculations. Integration regression verifies V1 routing for `222`/`333`/`444`, preservation of the legacy path for `555`, the single feature flag, legacy fallback and emergency legacy-2D fallback.

## Safety rules

- Do not delete `cube-preview.js`, `wca-previews.js`, `scramble-display`, or the TwistyPlayer path while V1 still has a legacy fallback dependency.
- Do not add CSS mirroring or face-specific transform patches. Orientation bugs belong in state mapping.
- Do not create a second state engine or renderer for the same NxN path.
- Keep colors out of state data.

## Recommended next step

Validate 5x5 against the same cubing.js reference adapter before changing its production route. Keep 5x5-7x7 on the legacy path until each event passes its own state, rendering and fallback regression gate.
