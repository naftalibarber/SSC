# SSC Native Preview V1

SSC's native cube preview infrastructure. The state engine and SVG renderer are owned by SSC; `cubing.js` is used only as an independent validation reference.

## Current scope

- Generic NxN state engine for orders 2-7.
- WCA-style outer and wide cube moves used by NxN scrambles.
- Normalized state output using face identities (`U D F B R L`), never colors.
- Deterministic semantic sticker IDs such as `U1`, `U2`, `F9`.
- Generic mathematical SVG net renderer shared by 2x2-7x7.
- Palette is applied only in the renderer and comes from SSC's existing `sscCubeColorsV1` settings.
- `cubing.js` reference validation for 2x2 and 3x3.
- Production routing for `222` and `333` behind one feature flag.
- Legacy preview fallback remains installed for render failures and for every other event.
- Development and validation UI at `/preview-lab.html`.

## Modules

```text
ssc-nxn-state.js
  State Engine

ssc-svg-renderer.js
  SVG Renderer

ssc-preview-validation.js
  cubing.js Reference Adapter + normalizeState() + compareStates()

ssc-preview-v1.js
  Public Facade

ssc-preview-v1-integration.js
  Production Routing + Legacy Fallback
```

## Data flow

```text
Scramble
  -> SSCNxNState
  -> normalized face state
  -> SSCSvgCubeRenderer
  -> SVG
```

Validation is intentionally separate from rendering:

```text
Scramble -> SSCNxNState -> normalized SSC state
Scramble -> cubing.js    -> normalized reference state
                         -> compareStates()
```

## Public APIs

### State

```js
const state = SSCNxNState.buildState("R U R'", 3, { strict: true });
```

State shape:

```js
{
  order: 3,
  moves: [...],
  ignoredMoves: [],
  faces: {
    U: [[...], [...], [...]],
    L: [[...], [...], [...]],
    F: [[...], [...], [...]],
    R: [[...], [...], [...]],
    B: [[...], [...], [...]],
    D: [[...], [...], [...]]
  },
  mapping: {
    U1: 'F',
    U2: 'U',
    ...
  }
}
```

### Renderer

```js
SSCSvgCubeRenderer.render(container, {
  scramble: "R U R'",
  order: 3,
  colors: SSCPreviewV1.getColors()
});
```

### Facade

```js
SSCPreviewV1.render(container, scramble, '333');

await SSCPreviewV1.validate({
  eventId: '333',
  count: 100

await SSCPreviewV1.validateAll();
```

## Production feature flag

There is one production flag, defined once in `index.html`:

```js
window.SSC_FEATURES = {
  previewV1: true
};
```

When enabled, only `222` and `333` are routed to `SSCPreviewV1`. All other events continue through the existing preview system.

If V1 throws during a `222` or `333` render, `ssc-preview-v1-integration.js` logs the failure and immediately calls the captured legacy renderer. If that connected renderer also fails, it makes one final attempt through the existing 2D preview manager.

## Validation baseline

Before production routing was enabled, CI validated each event with:

- solved state;
- all quarter, inverse, and double turns for `R U F L D B`;
- inverse pairs;
- four-turn identities;
- known algorithms;
- 100 WCA random scrambles generated by `cubing.js`.

Final state validation baseline: `134/134` passing cases for 2x2 and `134/134` for 3x3, with zero sticker mismatches.

Rendering regression checks cover solved/scrambled 2x2 and 3x3, stable semantic IDs, immediate color updates, scramble updates, no mirroring transforms, and 150/200/300/400 px scale calculations.

## Safety rules

- Do not delete `cube-preview.js`, `wca-previews.js`, `scramble-display`, or the TwistyPlayer path while V1 still has a legacy fallback dependency.
- Do not add CSS mirroring or face-specific transform patches. Orientation bugs belong in state mapping.
- Do not create a second state engine or renderer for the same NxN path.
- Keep colors out of state data.

## Recommended next step

Validate and integrate 4x4 against a trusted reference before changing its production route. Keep 4x4 on the legacy path until its own state and visual regression gate passes.
